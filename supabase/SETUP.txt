WAS SICH ÄNDERT (Stand 2026-09-21)
----------------------------------
Vorher: Access Key + Secret Key von Cloudflare R2 standen im Klartext in
        js/file-upload-service-r2.js und js/process-attachments.js. Jeder, der
        die Seite aufrufen konnte, hatte damit Vollzugriff auf den Bucket.

Nachher: die Schlüssel liegen EINMAL als Supabase Secrets auf dem Server.
        Der Browser fragt die Edge Function r2-sign, die prüft die Anmeldung
        (JWT) und gibt eine 5 Minuten gültige, signierte URL zurück (Upload,
        Download, Löschen) bzw. führt Umbenennen und Auflisten selbst aus.
        Das AWS-SDK (1 MB) wird nicht mehr geladen.

Function:  supabase/functions/r2-sign/index.ts
Client:    js/file-upload-service-r2.js  (FileUploadService.r2Sign, listFiles)
Projekt:   rtnpyziwyaqrlfazxkyr

WICHTIG: Ohne ausgerollte Function funktionieren Upload, Löschen, Umbenennen
und der PDF-Download der Mietvereinbarung NICHT mehr (Meldung "Edge Function
r2-sign ist nicht ausgerollt"). Also erst Schritt 1–3, dann die App verteilen.


================================================================================
SCHRITT 1 — NEUE R2-Schlüssel erzeugen (die alten gelten als verbrannt)
================================================================================
  https://dash.cloudflare.com → R2 → Manage R2 API Tokens → Create API Token
    Berechtigung: Object Read & Write, nur Bucket "dateien"
  → Access Key ID und Secret Access Key notieren (Secret wird nur einmal gezeigt)

  Das ALTE Token noch NICHT löschen — erst nach Schritt 4, sonst steht die
  App bis dahin still.


================================================================================
SCHRITT 2 — Secrets setzen
================================================================================
Weg A (CLI, wie bei groq-proxy):
  supabase secrets set R2_ACCOUNT_ID=855feaccf4d0215922275100e91c4656 R2_ACCESS_KEY=<neu> R2_SECRET_KEY=<neu> R2_BUCKET=dateien R2_PUBLIC_URL=https://pub-28aab7dd73f540f38b6358d78f889a27.r2.dev --project-ref rtnpyziwyaqrlfazxkyr

Weg B (Dashboard):
  https://supabase.com/dashboard/project/rtnpyziwyaqrlfazxkyr/settings/functions
  → Secrets → die fünf Werte einzeln anlegen.


================================================================================
SCHRITT 3 — Function ausrollen
================================================================================
Weg A (CLI):

Weg B (Dashboard, ohne CLI):

Prüfen (muss 401 liefern — kein Token mitgeschickt, genau richtig):

TECHNISCHER ABLAUF
================================================================================
upload:   Browser → r2-sign {action:'upload', path, contentType}
                  ← {uploadUrl, publicUrl};  Browser → PUT uploadUrl
download: Browser → r2-sign {action:'download', path} ← {downloadUrl}; GET
delete:   Browser → r2-sign {action:'delete', path} ← {deleteUrl}; DELETE
rename:   Browser → r2-sign {action:'rename', fromPath, toPath}  (serverseitig)
list:     Browser → r2-sign {action:'list', prefix} ← {keys:[…]} (serverseitig)
